# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

resilience4cata is an annotation-driven resilience library for plain Java 21+ (no Spring/CDI/AspectJ), designed to have lower overhead than Resilience4j. The project is in **phase 2: first code**. All six MVP policies are implemented end to end, sync and async: `@Fallback`, `@Retry`, `@CircuitBreaker`, `@RateLimiter`, `@Timeout` and `@Bulkhead`, plus `@Hedge` (async only, 0.4.0) and `@AdaptiveLimit` (0.6.0); plus the `config` module (external configuration), classifiers, the programmatic `Pipeline`, events and snapshots, the `testkit` module, and annotated classes (subclass style).

## How the pieces fit

- Each supported policy is a `Kind` in `ResilienceProcessor` (annotation, generated field prefix, runtime policy class, registry method, config class). Kinds are declared in nesting order, outermost first: `FALLBACK`, `RETRY`, `HEDGE`, `CIRCUIT_BREAKER`, `RATE_LIMITER`, `ADAPTIVE_LIMIT`, `TIMEOUT`, `BULKHEAD` (`RETRY` and `HEDGE` are exclusive on one method, so a hedge takes Retry's slot). `writeMethod` emits one layer per policy present: the public method holds the outermost layer, and each inner layer is a private method `r4c$<field><index>(...)` with the same signature, ending with the delegate call. Each layer builder (`retry`, `circuitBreaker`, `timeout`) receives the inner call as an expression. Adding a policy means a new `Kind` in the right position, its attribute validation in `policyModel`, a layer builder, a `*Config` record + builder, a `*Policy` class in `dev.resilience4cata.generated`, and registry methods.
- `processor` (`ResilienceProcessor`) scans every root element (`getSupportedAnnotationTypes` is `*`, because composed annotations are user-defined). For each interface that uses `@Retry`, directly, at type level or through a `@ResiliencePolicy` bundle, it writes a top-level class named `<binary name>$Resilient` (for example `Repository$Cache$Resilient`) in the same package. The class implements the interface, delegates every method, and holds one `final` `RetryPolicy` field per protected method.
- Annotated classes (subclass style, `SubclassWriter`): a `CLASS` root element is processed only if it declares a policy annotation itself (`usesAnyPolicy`); a class that only implements an annotated interface is not processed (it uses `Resilient.of`). `SubclassWriter.check` rejects final/sealed/abstract/inner/private classes, only-private constructors, and final or other-package package-private methods annotated at method level; type-level annotations skip final methods. `generateIfNeeded` is shared with interfaces: `members()` and `effective()` branch to `SubclassWriter` (precedence: interface type < interface method < declaring superclass types top-down < the class's type < class methods top-down; `Object` overrides take method-level only), and only methods with policies get a model. `write` emits `public class <binary name>$Resilient extends C` (not `final`, so CGLIB/scoped proxies can extend it; no `delegate` field), mirrors every non-private constructor as `(ResilienceRegistry registry, <params>)` with `super(...)` and the same field-init block (`appendFieldInits(out, methods, registryName)`); mirrored constructors keep the original parameter names and copy constructor and parameter declaration annotations through `AnnotationPrinter` (retention CLASS/RUNTIME, `@Target` allowing CONSTRUCTOR/PARAMETER; `@ConstructorProperties` gets the registry name first) for DI containers; the registry parameter has no annotation (injected by type) and is `r4c$registry` when a parameter is named `registry`; parameters named `java`/`dev`/`r4c$…` become `r4c$p<i>` (they would obscure qualified names in the init block); method overrides and their private layers keep the declared parameter names too (`SubclassWriter.parameterName`; Spring SpEL/MVC, Micronaut binding and Bean Validation read them on the invoked override), renaming the same names plus the first segment of a static fallback's receiver (`demo` in `demo.Service.fixed(...)`); interface wrappers keep `p0..pn` (byte-identical); the public override of every protected method repeats the overridden method's and its parameters' annotations (`AnnotationPrinter.methodAnnotations`/`parameterAnnotations`: same rules, minus `dev.resilience4cata.annotation.*`, annotations meta-annotated with one of them (bundles; otherwise `C$Resilient$Resilient` would be generated), `@SafeVarargs`, and Bean Validation annotations (`jakarta.`/`javax.validation.*` and custom constraints meta-annotated `@Constraint`: inherited from the overridden method anyway, and a repeated `@Valid` return value is HV000131); private layers and `r4c$recover` get none; type-level annotations are never copied), and `delegateReceiver` makes layers end with `super.m(...)`; fallback siblings are called on `this` (must not be private). `Resilient.create(type, registry, args...)` picks the generated constructor reflectively once (exact fit before varargs expansion; ambiguity or no match is an `IllegalArgumentException` that suggests `new C$Resilient(registry, ...)`). Methods a constructor calls on `this` run before the policy fields are set (documented, not guarded). Interface output must stay byte-identical.
- Native image: next to every generated class, `writeNativeImageMetadata` writes `META-INF/native-image/dev.resilience4cata.generated/<generated binary name>/reachability-metadata.json` (CLASS_OUTPUT, `createResource` with the type as only originating element; Native Image walks every subdirectory of `META-INF/native-image` and matches the file name) registering `allPublicConstructors`, conditional on `typeReached` of the interface, or of `dev.resilience4cata.Resilient` for classes (`Resilient.create(C.class)` may run before `C` is initialized), plus varargs array types for classes. Unified format = GraalVM for JDK 23+. `core` ships `META-INF/native-image/dev.resilience4cata/resilience4cata-core/native-image.properties` with `--initialize-at-run-time` for the lazy thread-starting holders `Watchdog$Shared`, `TimeoutTimer$Shared`, `AsyncSupport$Timer` (`NativeImagePropertiesTest`); a new class whose static init starts a thread must be a lazy holder listed there.
- Attribute merging is in `PolicyAttributes` (one instance per policy annotation): only explicitly set, non-sentinel values count. Precedence is declaring interface < wrapped interface < method; a direct annotation beats bundles; two bundles disagreeing is a compile error. Durations are parsed at compile time (`Durations`) and emitted as `Duration.ofNanos(...)`.
- Types in generated signatures are printed by `TypePrinter`, never `TypeMirror.toString()`, so type-use annotations such as `@Nullable` do not produce invalid source.
- At runtime, `Resilient.of(type, impl, registry)` loads `<type>$Resilient` once by name and calls its `(type, ResilienceRegistry)` constructor. The constructor calls `registry.retryPolicy(instanceId, name, config, overrides)`, which resolves defaults → named config → annotation overrides into an immutable `RetryConfig` and shares instances by `name`.
- The generated retry loop calls `RetryPolicy.start()`, `onFailure(attempts, e, start)` and `pause(delay)` (package `dev.resilience4cata.generated`, exported only for generated code). Nothing is allocated on the success path.
- Retry budget (`RetryBudget`, package-private, one per retry instance, so shared by every caller of a `name`/pipeline id; only built when `config.enabled() && config.hasBudget()`, i.e. `budgetPercent > 0`; the reserve `budgetMinRetriesPerSecond` defaults to 10, Finagle's default, and only applies once the percent turns the budget on, so a reserve alone is not a budget): retries in the last `budgetWindow` ≤ `budgetMinRetriesPerSecond × window s + budgetPercent % × calls in the window` (Finagle `RetryBudget` style; a gRPC-style token bucket was rejected because refunding on success is a shared write per call). Protocol: `RetryPolicy.start()` reads one `final boolean startsSlow` (= `maxDuration > 0 || budget != null`), so without a budget the path is one field read as before and generated code is unchanged; with one, `startSlow()` calls `budget.onCall()`: one lossy plain read-and-write (`getOpaque` + `setOpaque`; a race on a shared stripe can lose a call, which only lowers the budget; measured 3.5 ns vs 9.7 ns for a CAS loop and 12 ns for `getAndAddRelease` on Graviton3) on this thread's stripe (`RetryBudget.stripe`: Fibonacci-hashed thread id — the low bits alone put every JMH worker on one stripe; stripes = power of two ≥ 2 × CPUs, ≤ 64, 128-byte apart in one `long[]`), no clock, no allocation. `decide` asks `budget.tryAcquire(ticker)` last (after maxAttempts/interrupt/retryable/open-breaker/maxDuration), so refused retries cost nothing; refusal → `GaveUp(BUDGET_EXHAUSTED)`, `NO_RETRY`. `tryAcquire` sums the stripes and, if allowed, CASes the shared retry count (`weakCompareAndSetPlain`); an exhausted budget only reads. The window is cumulative counters plus immutable `Marks` (counts at the first failure of each of the last 10 tenths of the window), replaced by CAS at most once per tenth and only by failures: successes never read the clock, so calls made while nothing failed are dated at the previous mark (after a quiet period longer than the window they have expired: fewer retries, never more). `RetrySnapshot.budget()` = `Budget(calls, retries, allowedRetries)` via `RetryPolicy.budgetSnapshot()`, off the call path. Same in generated sync/async code and `Pipeline` because all go through `start()`/`decide`. Tests: `RetryBudgetTest` (fake clock, `RetryBudget(config, now, stripes)`), `RetryPolicyBudgetTest`, `RetryBudgetStress` (mutation-checked: plain stripe write, plain retry write, plain marks write). Benchmarks: `RetryBudgetBenchmark` (shared registries, `-t 1` and `-t 4`), budgeted at 0 B/op.
- `HedgePolicy` (`@Hedge`, async only: `checkHedge` reports `R4C-HDG-001` on a method without a stage result and `R4C-HDG-002` with `@Retry`, direct, type-level or bundled; `maxAttempts` outside 2..10 is `R4C-ATR-008`, budget values reuse `R4C-ATR-007`; `Pipeline.execute`/`run` with a hedge throws `R4C-RT-018`, retry + hedge in a pipeline `R4C-RT-019` at `build()`; no handle, `HedgeSnapshot` in `registry.snapshot().hedges()`). Generated code is one more `executeAsync` layer in Retry's slot (`asyncArguments` passes `this.fallback<i>, recovery` like the retry, so `FallbackContext.attempts()` = attempts started; sync output is unchanged). One call = one `HedgeCall extends TimerEntry implements BiConsumer, LinkedFuture.OnCancel`: the first delay's timer entry, attempt 1's callback and the returned `LinkedFuture`'s link. Its `progress` int (launched bits 0-3, failed bits 4-7, `SETTLED`, `STOPPED`) changes only by CAS; exactly one transition sets `SETTLED`, so late outcomes are dropped. First success wins; a failure's verdict (one `ClassValue`): `abortOn` or not in `hedgeOn` → `ABORT` (settle in the same CAS that counts it, cancel the rest); a rejection (`CallNotPermittedException`, `BulkheadFullException`, `RateLimitExceededException`) → `STOPPED` (no new attempt, in-flight ones kept); `hedgeOn` → launch the next attempt at once (`Hedged(FAILURE)`), never inline on the thread that completed the failed attempt (it may be a client's I/O thread): `launchSoon` calls `environment.later(0, …)`: a new virtual thread in production, on a manual ticker `ticker.schedule(0, …)` (runs at the next advance, deterministic); the task runs `launch(FAILURE, -1)` and, if nothing starts, `settleIfAllFailed`. After a failure that launches nothing, `settleIfAllFailed` ends the call with that (last) failure once failed == launched and no launch is possible. `launch(reason, armedFor)` checks open/not stopped/below max/not stale (`armedFor` = launched count the delay was armed for, `-1` for failures), asks the budget (`RetryBudget` reused via its `HedgeConfig` constructor; refused → `STOPPED` + `Skipped(BUDGET_EXHAUSTED)`; a token taken by a launch whose CAS then loses to the settlement is lost, which only lowers the budget), creates the `stages` array (one slot per attempt, by CAS) before the launch CAS, then publishes the attempt's stage with a CAS from `null` in its slot; the settler `getAndSet`s `DONE` into every other slot, so exactly one of them cancels a stage that raced the settlement (no store-buffering pair: one location per slot). Losers get `completeExceptionally(new HedgeCancelledException(id))`: one stackless instance per loser (message built in `getMessage()`), never shared, allocated only after a hedge fired or the call ended early (a `CancellationException`, so a `LinkedFuture` inside forwards it: the breaker `release`s, the bulkhead frees the slot); non-CF futures get `cancel(true)`. Delays: production on `TimeoutTimer` (one lane per policy; the first delay is the `HedgeCall` itself, later ones a `Next` entry; never early, ≤ ~2 ticks late; a short delay shrinks the shared tick); on a manual ticker through `environment.later` (exact, hedges start inline on the advancing thread), cancelled tasks are taken off the ticker so `pendingTasks()` stays exact. `timer` holds the pending delay (`replaceTimer` keeps only the newest, `DONE` after settling). `delay = 0` launches every attempt on the caller's thread. A first attempt whose `CompletableFuture`/`LinkedFuture` already succeeded returns a `completedFuture` copy with no timer; otherwise the success path allocates the `HedgeCall`, its `LinkedFuture`, and `whenComplete`'s node and dependent future, reads no clock, and does one budget `onCall` (lossy stripe write). Events `HedgeEvent.Hedged/Won/Skipped/Failed` (`Won` only for attempt ≥ 2; `Failed` for every failed call); metrics `r4c.hedge.hedged|won|skipped|failed` in both metrics modules. Tests: `HedgePolicyTest` (manual ticker and manual `TimeoutTimer`; `startForTest`, `launch`, `verdictForTest` seams; mutation-checked: slot CAS, `SETTLED` check in `launch`, loser cancellation, breaker release), `HedgeProcessorTest`, `HedgeRegistryAndPipelineTest`, `HedgeOnManualClockTest` (testkit), `HedgeEndToEndTest` and `PipelineEquivalenceTest.aHedgeStartsAndCancelsTheSameAttempts` (examples), `HedgeStress` (jcstress, mutation-checked). Benchmarks: `HedgeBenchmark` (fast path, pending, no budget, hedge fires, `resilience4j-hedge`, hand-written CF), in the allocation gate at its measured async bytes.
- `CircuitBreakerPolicy` (also the public `CircuitBreakerHandle` returned by `registry.circuitBreaker(id)`, with `forceOpen`/`disable`/`reset`): the state is an immutable `Phase` (`Closed`/`Open`/`HalfOpen`/`ForcedOpen`/`Disabled`) swapped by CAS through a `VarHandle`; objects are allocated only on transitions. Every transition goes through `transition(...)`, which swaps the phase and then clears `quiet`. `Closed` holds a `SlidingWindow`: `CountWindow` (default) or `TimeWindow` (one-second buckets, `LongAdder` counters, never quiet because every success must be counted). `acquire()` returns the phase's generation as the token, and outcomes with a stale token are dropped. `CountWindow` is a slot array updated with `getAndSet` plus counters, and skips rewriting a slot that already holds the same outcome. While closed with a window of only fast successes, the policy's `quiet` field holds the generation and `acquire`/`onSuccess` read only that field (ordering: count a failure before clearing `quiet`; set `quiet` before re-checking the window). Reads of `phase`/`quiet` are opaque, which is safe because everything they reach is `final`.
- Performance rules learned while tuning the breaker (see `docs/en/benchmarks.md`): under contention, writes to shared cache lines cost far more than locks or atomics save, so never write a value that does not change and keep per-call-written fields (the window cursor) apart from read-mostly ones. On ARM, avoid acquire/volatile reads on the hot path where `final`-field publication already suffices, and use the weakest atomic that is correct (`compareAndExchangeAcquire` to take a permit, `getAndAddRelease` to give it back): full-fence atomics cost 2–3× more there. Measure single-thread and multi-thread, success and mixed, after every hot-path change: improvements to one case have regressed another more than once. Rejections throw one preallocated, stackless `CallNotPermittedException` per breaker. Calls are timed only if `slowCallDuration` is set. `RetryPolicy.decide` never retries a `CallNotPermittedException` (an implicit abort that wins over `abortOn`, `retryOn` and classifiers, in generated sync/async code and `Pipeline`), so an open breaker stops retries; `RetryConfig.DEFAULTS.abortOn` is empty.
- `TimeoutPolicy` + `Watchdog`: one shared daemon thread publishes a coarse clock and checks, every tick, a per-thread stack of reusable `Scope`s; timed calls read no clock and write only their own scope. A scope's state is a stamp (call number in the high bits, state in the low two) so a watchdog that read an earlier call cannot interrupt the next one (ABA). On the caller side, `RUNNING → IDLE` by CAS; if the watchdog won, wait for `TIMED_OUT`, clear the interrupt, throw `CallTimeoutException`. Tests use a manual `Watchdog(0)` advanced with `tick(nanos)`. RUNNING→IDLE is `compareAndExchangeAcquire` (release alone would let the next call's start/limit be seen with this call's stamp → early interrupt). The Watchdog's coarse clock advances by at most one tick per tick (`advance`), so a late wake-up of the watchdog thread can't make calls look older than they are; it parks ¾ of a tick. Async timeouts use `TimeoutTimer` (not `AsyncSupport.later`, which stays on an STPE for precise retry and rate-limiter delays): `schedule` is one release CAS onto a per-thread-id striped inbox; each tick the timer thread unlinks cancelled entries, drains the inboxes (deadline = clock at drain + duration, so never early), and fires expired lane heads on virtual threads; at most ~2 ticks late. `TimerEntry` states go NEW→SCHEDULED→FIRED, or →CANCELLED by CAS. `executeAsync` skips the timer for a `CompletableFuture` that is already complete. Tests use `new TimeoutTimer(launched::add)` with `tick(now)` or the separate steps `drainCancelled/drainNew/expire`.
- `BulkheadPolicy` (also `BulkheadHandle`, from `registry.bulkhead(id)`): with `maxWait = 0`, a CAS loop on a counter in a padded object; a full bulkhead only reads. With `maxWait > 0`, a non-fair `Semaphore`. `waitingCalls()` = queued async waiters + `Semaphore.getQueueLength()` (0 without `maxWait`); monitoring only, never on the hot path. An interrupted wait is a rejection with the interrupt flag set again, so an outer `@Timeout` turns it into `CallTimeoutException`. Async calls with `maxWait > 0` never block: a full bulkhead queues a `BulkheadWaiters.Waiter` (FIFO `ConcurrentLinkedQueue` plus a padded volatile `count` of unclaimed waiters), whose one-shot state is CASed `WAITING → CLAIMED` by either the hand-off or its timeout (`AsyncSupport.later`), never both. `exit()` releases the permit, then does one volatile read of `count`; if it is positive it takes a permit back and gives it to the oldest live waiter on a new virtual thread. Enqueue order is count++ → offer → timer → drain, so release/read and count/tryAcquire form a store-buffering pair with volatile accesses on both sides: no lost wake-up. A drain that loses the permit hands nothing off; a permit no live waiter can take goes back to the semaphore. When sync threads are blocked too, every other hand-off leaves the slot to them (approximate: woken sync threads can win anyway). Tests replay the races through `enqueueForTest`/`drainForTest`/`Waiter.claim()`.
- `AdaptiveLimitPolicy` (`@AdaptiveLimit`, sync and async, also `AdaptiveLimitHandle` from `registry.adaptiveLimit(id)`; `Kind.ADAPTIVE_LIMIT` between rate limiter and timeout, so inner timeouts and full bulkheads are its drops): a concurrency limit moved by Netflix concurrency-limits 0.5.4's `Gradient2Limit` (default) or `AIMDLimit`, ported in the package-private sealed `LimitAlgorithm` (plain state, touched only under the window lock). Generated sync layer: `long start = acquire()` (throws the preallocated stackless `LimitExceededException`; a full limit only reads) → `onSuccess(start)` / `onFailure(start, e)`; `release()` for async cancellation; `executeAsync` like the breaker's. In-flight: the bulkhead's padded `compareAndExchangeAcquire`/`getAndAddRelease` counter; `decrement` returns the count before, which is the sample's in-flight value. The limit, the window deadline and a window lock live in one padded read-mostly `Window` object (opaque limit/deadline, CAS lock tried only when it reads 0). Samples: two clock reads per call through the ticker; a sample (success, or a failure in `dropOn`, `ignoreOn` winning; other failures only release) goes to this thread's 128-byte stripe (`RetryBudget.stripe`) of **cumulative** sum/count/drops with lossy opaque read+write (never reset, so a racing write loses an increment but never resurrects a used count) plus a per-window max in flight (reset by the closer; lossy). A completion with `end - deadline >= 0` calls `endWindow`: take the lock, re-check the deadline, sum stripes, and if `count - usedCount >= minWindowSamples` run the algorithm on the window's average RTT (≥ 1 ns), max in flight and drop flag, set the next deadline (`end + window`), store the limit and publish `LimitChanged` if it moved; otherwise it only moves the deadline to `end + window` and keeps the samples (usedCount/usedSum/usedDrops and the max in flight untouched; Netflix discards them), so an under-sampled limiter locks and scans once per window. No background thread; windows end only on completions. Events `AdaptiveLimitEvent.Rejected/LimitChanged`; metrics `r4c.calls.rejected{kind=adaptivelimit}`, `r4c.adaptivelimit.limit.changes`, gauges `r4c.adaptivelimit.limit` and `.concurrent.calls`; snapshot `AdaptiveLimitSnapshot` in `ResilienceSnapshot.adaptiveLimits()` (old 5- and 6-list constructors kept). Hedge treats `LimitExceededException` as `REJECTED`. Processor: `R4C-ATR-009` (bounds out of order among those set on the annotation, `window` outside 10ms..1h); tuning (`minWindowSamples`, `smoothing`, `rttTolerance`, `longWindow`, `queueSize`, `backoffRatio`) is config-only. Gradient2 does not go much below `2 × queueSize` by latency (fixed point of 0.9e + 0.2q). Tests: `AdaptiveLimitPolicyTest`, `LimitAlgorithmTest` (Netflix formulas), `AdaptiveLimitRegistryAndPipelineTest`, `AdaptiveLimitProcessorTest`, `AdaptiveLimitOnManualClockTest` (testkit), `AdaptiveLimitPageTest` and `PipelineEquivalenceTest.anAdaptiveLimitMovesItsLimitTheSameWay` (examples), `AdaptiveLimitStress` (mutation-checked: slot CAS, release, window lock; seams `tryLockWindowForTest`, `endWindowForTest`, `windowsForTest`, the `(id, config, env, stripes)` constructor). Benchmark `AdaptiveLimitBenchmark` (vs `@Bulkhead` and Netflix `SimpleLimiter` + windowed `Gradient2Limit`, fairness in its Javadoc), budgeted 0/0/48 B.
- `FALLBACK` is special: it has no registry entry, `name` or `config`, and is validated by `fallbackModel` (handler class or sibling methods) into a `FallbackModel` on `MethodModel`, not into `policies`. Its statements come from `fallbackLines`, which always end the method and expect the failure in a catch parameter named `r4c$e` (so `throw r4c$e` is a precise rethrow). Without `@Retry` it is its own outermost layer; with `@Retry` it is fused into the retry layer's give-up branch, which is how `FallbackContext.attempts()` gets the count without per-call allocation. Sibling methods are sorted most specific exception first; emission stops after the first one that catches everything, since later code would be unreachable. The runtime side, `FallbackPolicy`, only runs after a failure: `handles` (cached per class, `skipOn` wins), `context(...)`, and `unchecked(...)` for handler exceptions the method does not declare. Generic methods: `fallbackTargets` maps the candidate's type variables to the method's by position (`typeParameterRenaming`, bounds compared after `substitute`), and calls siblings and `r4c$recover` with explicit type arguments (`this.delegate.<T>name(...)`). A handler is rejected when the result type mentions the method's type variables.
- `config` (`ResilienceConfig`): reads classpath resources, files, `Properties`, environment (`R4C_…`) and system properties (`r4c.…`) into typed settings (keys parsed by `Key`, env names by backtracking in `Sources.EnvironmentNames`, attributes declared once per policy in `PolicyType`), applies profiles and flattens `extends`, validates eagerly against the built-in defaults, and registers `*Defaults`/named configs on a `ResilienceRegistry.Builder` via `applyTo`. Adding a policy attribute means one `Attribute` line in `PolicyType`. Every problem is collected into one `ConfigException` with an `R4C-CFG-nnn` code, the key's source (file and line) and a suggestion. `PropertiesReader` mirrors `java.util.Properties` syntax but keeps line numbers. Its `Durations` duplicates the processor's grammar: keep them in sync. Per-instance overrides `instances.<id>.<policy>.<attribute>` (`Key.Section.INSTANCE`; ids other than `[A-Za-z0-9_-]+` are double-quoted, split by `Key.segments`; env vars only for lowercase names) are registered with `Builder.<policy>Instance(id, …)` and applied by `ResilienceRegistry.resolve` after the annotation overrides, once at instance creation. External named configs go through `Builder.<policy>Overlay(name, …)`, applied after the code's `<policy>(name, …)` whatever the order, so code and external merge, external winning (R4C-CFG-011 is no longer reported). `PolicyType.validateInstances` reports a combination only when the instance sets every attribute that the message names, because the real base (the annotation) is unknown at build time. `ResilienceConfig.verifyInstances(registry)` checks ids against `registry.snapshot()` (R4C-CFG-013). `locked = true` (boolean on the 7 configurable annotations, merged like other attributes; the processor passes `, true` as a fifth argument to `registry.<kind>Policy(...)` only when locked and at least one attribute is set, so other output is byte-identical; `Pipeline.Builder.locked()`): `ResilienceRegistry.resolve` applies annotation values, then instance overrides, then the annotation values again; when that changes the result it records a `LockedOverride(policy, instance, config)` once per instance (`registry.lockedOverrides()`) and logs a `System.Logger` warning. `verifyInstances` reports each external key a locked instance ignored as R4C-CFG-014 (`PolicyType.changes`: applying the setting alone to the resolved config changes it). Named configs/defaults are unaffected (an annotation already beats them).
- `RateLimiterPolicy` (also `RateLimiterHandle`, from `registry.rateLimiter(id)`): GCRA on one padded `long`, the theoretical arrival time `tat`. Each permit moves `tat` by `interval = period / permits`; a call passes if `tat` stays within `permits × interval` of now. One loop serves both modes: if the needed wait exceeds `maxWait` (0 when fail-fast) it rejects without writing, otherwise a CAS reserves the slot and the caller sleeps until it is due (an interrupted sleep gives the permit back). A caller that loses the CAS parks for 1 ns before retrying: under contention that cut 658 → 131 ns per call with four threads, where other atomics, spinning and `Thread.yield()` did not help. `tat` guards no other memory, so it uses plain CAS (`weakCompareAndSetPlain`) and opaque reads. nanoTime values are compared by subtraction, never `Math.max`, because they can wrap. Tests use the package-private constructor with a fake ticker and sleeper.
- Error codes: every error the processor reports goes through `ProcessorError` (`error(element, ProcessorError.X, detail)`, which prefixes `[R4C-<AREA>-nnn] `); runtime misconfiguration uses the package-private `ErrorCode` in core: `R4C-RT` for `Resilient`/`Pipeline.Builder`, `R4C-REG` for `ResilienceRegistry`, its builder and the `*Config` builders (`ErrorCode.invalidValue(kind, detail)` for config validation; registry wrappers embed `ErrorCode.detail(e)` and keep the cause; config's `PolicyType.detail` strips the REG-001 prefix inside `R4C-CFG-006`; lookups use core's package-private `Suggestions.didYouMean`); config uses `ProblemException`'s constants; `testkit` (`R4C-TK`) and `junit` (`R4C-JU`) each have a package-private `ErrorCode` enum with `prefix()`, and an `ErrorCodeTest` that checks uniqueness, both docs languages, and that every code is thrown (junit: reported by an `EngineTestKit` fixture). A message says where, what and how to fix (with "Did you mean …?" when a name is looked up). Codes are stable: a new error takes the next free number of its area, never renumber or reuse one, and a retired code stays in the enum and keeps its section in the docs, marked retired. Each new code needs a `### R4C-…` section in both `docs/en/errors.md` and `docs/es/errors.md` (same headings, same order, identical code blocks). For a processor code, the first `java` block of the section is the wrong example and must report the code, and the second is the fix and must compile with no diagnostics (`ErrorCodeTest` compiles them; a block can hold several files, each introduced by a `// path/Name.java` line). In core, add a trigger to `ErrorCodeTest.everyCodeIsThrown`. Every runtime error has a code.

- Async: a method returning `CompletionStage<T>` or `CompletableFuture<T>` (concrete `T`; `asyncResult` in the processor) is generated by `writeAsyncMethod` as one expression of nested `policy.executeAsync(() -> next)` calls, innermost the delegate, with `AsyncCall<T>` (may throw) as the lambda type. A fallback becomes a private `r4c$recover<index>(Throwable, int attempts, params...)` returning a stage, passed as a `Recovery<T>` to `RetryPolicy.executeAsync(call, fallback, recovery)` (so it gets the attempts) or to `FallbackPolicy.executeAsync`. This deliberately breaks the straight-line rule: async calls allocate futures and go through megamorphic `CompletableFuture` callbacks anyway, so a lambda per layer costs little there; the sync path is unchanged. `AsyncSupport` holds the single daemon timer (`ScheduledThreadPoolExecutor`, remove-on-cancel) and hands every fired task to a new virtual thread, so user callbacks never run on the timer. Failures are always unwrapped from `CompletionException`/`ExecutionException`. Wildcard stages: `asyncResult` returns the upper bound `X` of `? extends X` (`Object` for `?`); `writeAsyncMethod` wraps the delegate call in `AsyncCall.<X>widen(...)` (a zero-allocation cast in core, safe because policies only read stages), and fallbacks/handlers returning `CompletionStage<? extends X>` are widened the same way (`widens` in `FallbackTarget`/`FallbackModel`). Downward cancellation: every policy returns a package-private `LinkedFuture` (final `CompletableFuture` subclass, replaces the old `new CompletableFuture<>()`; its one `volatile Object inner` fits the alignment padding, so bytes per call are unchanged) linked to what the policy waits for now: the inner stage, a retry backoff timer, or a policy hook (`LinkedFuture.OnCancel`: bulkhead `Waiter`, timeout `Expiry`, rate limiter `DelayedStart`). `cancel`/`completeExceptionally(CancellationException)` first swaps the link for a `CANCELLED` mark (`getAndSet`), cancels what it held (`cancelInner`: hook, or `Future.cancel`, UOE from minimal stages swallowed), then completes; so the inner callbacks, which run on the cancelling thread, see `cancelling()` and the caller's callbacks run after the inner layers let go. Policies complete their future with `fail(...)`, never the overridden `completeExceptionally`. `link(next)` is a CAS loop (fails and cancels `next` once the mark is in); `linkFirst`/the constructor are a plain store before the future is returned (publication is safe through the return, `whenComplete` or the timer; a release store there compiled to two `dmb ish` per call on aarch64 and cost ~5 ns per async layer on Graviton); `replace(expected, next)` is for the retry backoff, whose timer task may link the next attempt before the timer is linked. Exactly-once comes from that single field: a bulkhead slot is released only by the stage's completion callback (cancelling a `CompletableFuture` stage completes it at once), or by `runGranted` when it loses `link(STARTING)`; a rate-limiter `DelayedStart` gives its permit back only if the cancel finds the hook before `run` links `STARTING`. Reactions: breaker `release(token)` on a failure while `cancelling()` (no classify, no record); retry `accept`/`run` return when `cancelling()` (no events, no fallback); `FallbackPolicy.recoverOrFail` returns at once when cancelling and links the recovery stage; timeout `Expiry.cancelled` cancels its `TimerEntry` and the stage; a timeout that fires cancels the inner layers via `cancelInner(stage)`. `TimeoutPolicy`'s already-complete shortcut accepts `LinkedFuture.class` too (inner policy futures), and `Pipeline.executeAsync` returns the outermost policy's future as is (`Layer<T>`, covariant `AsyncCall`), never wrapped. Tests: `AsyncCancellationTest` (core), `AsyncCancellationEndToEndTest` (examples), `CancellationStress` (jcstress). Generated code is unchanged.
- `classifier` (`@Retry`/`@CircuitBreaker`): validated by `ResilienceProcessor.classifier(...)` (concrete, non-generic, accessible no-arg constructor, implements `Classifier<X>` with the value type assignable to `X`); `PolicyModel.classifier` holds the class name. Each method gets a `final` field `<field>Classifier<index>`; the breaker reuses the retry's when the class is the same. Methods without a classifier generate byte-identical code. Layers `classifiedRetry`/`classifiedCircuitBreaker` call `classify` directly (monomorphic), then `RetryPolicy.onFailure(..., Outcome)`/`onFailedResult` or `CircuitBreakerPolicy.onFailure(..., Outcome)`/`onResult` (`IGNORE` → `release`, which returns a half-open permit). Every retry decision goes through the private `RetryPolicy.decide`. The classifier replaces `retryOn`/`recordOn` (combining them is a compile error); `abortOn`/`ignoreOn` win first. On an exhausted `FAILURE` result the layer returns the last result, or with `@Retry(onExhaustedResult = THROW)` (annotation-only, decided at compile time, not in `RetryConfig`; `PolicyModel.throwOnExhaustedResult`; compile error without a classifier) throws `r4c$retry.rejected(result, attempts)`, a `ResultRejectedException`; with a fallback it is thrown inside `try { … } catch (Throwable r4c$r)` so that `fallbackLines(r4c$r)` gets a precise rethrow. Async: the `executeAsync(call, classifier, boolean throwOnExhaustedResult, fallback, recovery)` overload. A throwing classifier fails the call: the breaker records `FAILURE`, the retry gives up through the fused fallback (`fallbackLines` takes the failure variable name, here `r4c$c`, with `attempts + 1`), after `r4c$retry.onClassifierFailure(attempts + 1, r4c$c)`, which publishes `GaveUp(CLASSIFIER_FAILED)` if someone listens (the same in `AsyncAttempts` and `Pipeline`). A breaker classifier that throws must not be re-classified by the retry around it: inside a retry (compile-time `model.policies().containsKey(RETRY)`), `classifiedCircuitBreaker` records `FAILURE` and throws `new ClassifierFailure(r4c$c)` (public, stackless, `generated`; allocated only when a classifier throws), and every retry layer over a classified breaker (`retry` too, without a classifier of its own) gets an extra `catch (ClassifierFailure r4c$w)` before `catch (Throwable r4c$e)` that does `try { throw r4c$w.failure(); } catch (Throwable r4c$c) { onClassifierFailure; give up }` (precise rethrow; `failure()` throws non-`RuntimeException`s). Without a retry the breaker rethrows the classifier's exception as is. Async: `CircuitBreakerPolicy.executeAsync(call, classifier, insideRetry)`, unwrapped in `AsyncAttempts.accept`; `Pipeline` mirrors it (`classifierFailure(...)` wraps only if `retry != null`; `retrying`/`classifiedRetrying` catch it). A wrapper never leaves a generated method. Classified `@Retry` layers, retry layers over a classified breaker, and classified breakers inside a retry are therefore not byte-identical to before these changes; everything else is. Async uses the `executeAsync(call, classifier, ...)` overloads.

- `PolicyEnvironment` (generated) is built once per registry by `PolicyEnvironment.of(ticker, random)` from `Builder.ticker(Ticker)`/`random(RandomGenerator)`, plus `withEvents(EventDispatcher)`, and passed to every policy's `(id, config, env)` constructor; policies copy what they need into `final` fields. `DEFAULT` shares one `System::nanoTime` lambda (call sites stay monomorphic) and `ThreadLocalRandom` (`random == null`, checked only on the retry failure path). With a `Ticker` (testkit's `ManualClock`): reads and sleeps go to the ticker, async delays (`env.later`, used instead of `AsyncSupport.later` by every policy; on a ticker every delay goes to `ticker.schedule`, zero included, so a zero-delay async retry or a hedge after a failure runs at the next advance, `advance(Duration.ZERO)` included, never on a virtual thread; without a ticker, a non-positive delay still starts a virtual thread at once) and async timeouts go to `ticker.schedule`, and sync timeouts use a per-registry `Watchdog.manual` (tick 0, no slack) ticked through `ticker.onAdvance`. The deadline CASes `WAITING→DECIDING`, takes a free permit for the waiter if there is one (`GRANTED`) or `TIMED_OUT`, interrupts, then publishes the decision. The waiter CASes `WAITING→DONE`; if it loses, it waits for the decision and clears the interrupt. If both acquired, the extra permit is released; an acquired permit is kept even after `TIMED_OUT`. ## Decisions to respect

- **Java 21 baseline** (`--release 21`), tested on 21 and 25; the one documented exception is the `micronaut` module (`--release 25`, because Micronaut 5 needs Java 25). Do not use APIs that are preview or newer than 21 (e.g. `StructuredTaskScope`, the Class-File API) in published modules.
- **No Kotlin anywhere**, including the build. Gradle uses the Groovy DSL, kept minimal and declarative (`settings.gradle`, short `build.gradle` per module). All build logic goes in convention plugins written in Java under `conventions/src/main/java` (plugin `r4c.java-library`: Java 21 toolchain, `--release 21`, `-Xlint:all -Werror`, JUnit Platform, `resilience4cata-<module>` jar names). Versions live in `gradle/libs.versions.toml`.
- Interfaces referenced by annotations (`FallbackHandler<T>`, `Classifier<T>`) live in `core`; annotation attributes are `Class<?>` and the processor checks the type. This keeps `annotations` `compileOnly`.
- **Coordinates**: groupId `dev.resilience4cata` (the project owns `resilience4cata.dev`); root Java package and JPMS module prefix `dev.resilience4cata`.
- **`annotations` is a separate module from `core`.** Durations in annotations and config are strings (`"250ms"`, `"2s"`, `"PT2S"`), validated by the processor.
- **Modules have single-word names**: `annotations`, `core`, `processor`, `config`, `all` (no code: a `module-info` and `api` dependencies on `core`, `annotations`, `config`; its Javadoc jar holds only `src/javadoc/README.txt`), `micrometer`, `testkit`, `spring`, `micronaut`, `bom`, plus unpublished `site`, `benchmark`, `stress`, `examples`. The one exception is the Quarkus extension, nested as Quarkus expects: `quarkus:runtime`, `quarkus:deployment` (published) and `quarkus:it` (unpublished). Never name a module `test` (clashes with Gradle's `test` task). Published artifactIds get the `resilience4cata-` prefix.
- **Annotations are handled by a compile-time annotation processor (`processor`) that generates plain Java source.** No runtime proxies, bytecode generation, AspectJ or agents in `core`. The processor is **mandatory**: if a generated class is missing, `Resilient.of` must fail fast with a message showing the `annotationProcessor` dependency to add; there is no reflection fallback. Annotations use `CLASS` retention, so `annotations` is a `compileOnly` dependency for users.
- **`core` and `annotations` have zero external dependencies** (JDK only, except JSpecify as an `api` dependency of `core`). `processor` is only ever an `annotationProcessor` dependency. Generated code may only use `core`'s exported generated-code API.
- **Generated code must be straight-line and per method**, calling the allocation-free permit protocol in `core` (acquire / onSuccess / onFailure). Do not route generated code through a shared lambda executor: our JMH run showed it doubles the overhead once several services share it (see `docs/en/research/02-annotation-mechanisms.md` §3).
- **Hot paths**: no allocation on success paths, no locks and no `synchronized` (pinning on JDK 21), one clock-read pair per call, preallocated stackless rejection exceptions, events allocated only when someone listens. Configuration is resolved once at instance creation, never per call, and is immutable afterwards: there is no hot reload or `reconfigure()` API, by decision.
- **Interface vs implementation annotations**: with `Resilient.of(interface, impl, registry)` only interface annotations count ; an annotated implementation class is itself processed in subclass style (used through `Resilient.create`/`new C$Resilient(...)`), where its annotations win attribute by attribute: interface < interface method < class < class method.
- **Self-invocation is intercepted** in the generated-subclass style (`this.other()` goes through the override). It cannot be intercepted in the interface-wrapper style; that limit is documented, not worked around.
- Default policy order, outermost first: `Fallback → Retry|Hedge → CircuitBreaker → RateLimiter → AdaptiveLimit → Timeout → Bulkhead → method`.

Where tests go:
- `core`: unit tests of policies and config. `RetryPolicy` has a package-private constructor that takes a fake clock and sleeper.
- `processor`: compile Java sources in-memory with the processor via the `Compilation` helper (plain `javax.tools`, no compile-testing library) and assert on errors or generated source. Compilation uses `-Xlint:all -Werror`, so generated code must be warning-free.
- `examples`: annotated interfaces under `src/test/java` are processed by `testAnnotationProcessor project(':processor')`; tests call `Resilient.of(...)` on them. Generated sources land in `examples/build/generated/sources/annotationProcessor/java/test`.
- `testkit`: tests of `ManualClock` and of the policies driven through a registry on a manual clock. Users' own deterministic tests should use it too (see `TestkitEndToEndTest` in `examples`).
- `micronaut`: Micronaut contexts (`ApplicationContext.run`, `@MicronautTest`) over fixture beans on the test class path, compiled with Micronaut's processor and ours and `-Ar4c.inject=micronaut`. Every bean there exists in every context: guard new fixtures with `@Requires` (a property or the `guide` environment) unless all tests can live with them.
- `quarkus:it`: the Quarkus extension's tests. `@QuarkusTest` in `src/test` (the guide's application in `src/main`); `QuarkusExtensionTest` applications and their fixtures in `src/extensionTest` (task `extensionTest`). A new `R4C-QK` code needs a trigger test class and an entry in its `ErrorCodeTest.TRIGGERS`.
- `stress`: jcstress tests (`@JCStressTest`) of the lock-free policies. `./gradlew build` only compiles them; they run through the `jcstress` task (plugin `r4c.jcstress` in `conventions`: annotation processor plus `org.openjdk.jcstress.Main`, no third-party Gradle plugin). Tests that need package-private seams (fixed clocks, `Watchdog(0)`/`tick`, stale stamps) live in package `dev.resilience4cata.generated`, which works because `stress` is not modular, so `core` is on the class path. Check every new test by mutation, as for other race tests. Rerun them after any change to a lock-free policy.

The build runs on any JDK ≥ 17 and compiles with a Java 21 toolchain, plus a Java 25 one for `micronaut` (auto-detected locally; CI installs both). Configuration cache is on: build logic must stay configuration-cache compatible.

- Docs are plain Markdown, **bilingual**: `docs/en/**` and `docs/es/**` must have the same file tree. English is the source of truth; any change to an English doc must be mirrored in the Spanish one. Code and identifiers stay in English in both.
- `docs/` is the public site (https://resilience4cata.dev): Docsify 4, in history mode (real paths `/en/start/quickstart`; old `#/en/…` links are redirected by the bootstrap script in `docs/index.html`, whose asset paths are absolute `/_media/…`). Authoring has no build step, but the deployed site is `site/build/site`: the unpublished `site` module (`SiteGenerator`, commonmark-java) copies `docs/` and adds one pre-rendered HTML page per Markdown page (`en/x/y.md` → `en/x/y.html`, a folder's `README.md` → `index.html`; GitHub Pages serves `x.html` for `/x`) with its own `<title>` (`<h1> · resilience4cata`), description (the lede), canonical URL, `hreflang` en/es/x-default and the rendered content in `#app` (hidden by the `r4c-js` class; Docsify replaces it), plus `404.html` (shell, `noindex`), `sitemap.xml` and `robots.txt`. `.github/workflows/site.yml` runs `./gradlew :site:generate` and deploys with the official Pages actions on every push to `main` touching `docs/` or `site/` (Pages source: GitHub Actions). `SiteGeneratorTest` checks every page's head, that generated links resolve, and that the shell has no hash routes; `docs/index.html`'s `<title>`, canonical and `<meta>` tags are replaced by exact text, so keep their shape. `r4c.js` sets `document.title` like the generator and rewrites Docsify's `/x/README` links to `/x/`. Theme and plugins are ours: `docs/_media/theme.css` and `docs/_media/r4c.js` ("Breaker panel" design); third-party scripts in `docs/index.html` are pinned to exact versions. Sidebars are `docs/en/_sidebar.md` and `docs/es/_sidebar.md` (absolute links `/en/x.md`; prev/next follows their order); add every new page to both. User pages: `start/`, `policies/`, `guides/`, `reference/`, `migrate/`, `performance.md`, `faq.md`, `changelog.md`, `blog/` (dated articles, index in `blog/README.md`, newest first; in the header nav and both sidebars; their `java` blocks are checked by `DocsTest` like guides; they keep the versions they were written for, so leave them out when bumping versions after a release); contributor pages (`design.md`, `architecture.md`, `benchmarks.md`, `releasing.md`, `research/`) form the "Project" group. The landing pages `docs/{en,es}/README.md` are raw HTML with no blank lines (write empty lines inside `<pre>` as `<span></span>`; links as `/en/…`).
- Page conventions: `# Title`, then a one-sentence lede; `##`/`###` feed "On this page"; relative `.md` links (`../errors.md#r4c-atr-001`; Docsify heading ids are the lowercased heading text, or `:id=` when set). Components: tabs `<!-- tabs:start -->` + `#### **Gradle**` / `#### **Gradle (Kotlin)**` / `#### **Maven**` + `<!-- tabs:end -->` (keep these labels: the choice is remembered by label); callouts `> [!NOTE|TIP|IMPORTANT|WARNING|CAUTION|MEASURED]` (MEASURED for every performance statement, citing its `benchmarks.md` section); `<!-- compare:start -->` snippet + `<!-- not-compiled: generated code, abridged -->` block `<!-- compare:end -->` (real generated code from `examples/build/generated/...`); facts strip `<div class="r4c-facts">` + one-row table; Mermaid fences without hard-coded colours (`:::closed`/`:::open`/`:::half`/`:::signal`), and no reserved words such as `call`/`end` as node ids (a parse error shows the diagram as source).
- Every code block on a site page is tested: `<!-- snippet: id -->` above a fence must equal the region `// tag::id[]` … `// end::id[]` (or `# tag::`) of a file under `examples/src/test` (code in `examples/.../examples/docs/<page>/`, in tests whose assertions prove what the page says); in `start/`, `policies/`, `guides/` every `java` block is a snippet or has `<!-- not-compiled: reason -->`. `DocsTest` enforces this, the en/es tree parity, and the same snippet order per page pair. `ConfigurationReferenceTest` (config) checks `reference/configuration.md` against `PolicyType` and the `*Config` defaults: a new policy attribute needs a row in both languages. The Micrometer recipe in `guides/observability.md` uses `micrometer-core` as a test-only dependency of `examples`; there is no `micrometer` module. Build snippets write the version literally (`0.1.0`): update them on every release.
- Research docs tag claims as verified, measured or inferred. Keep that discipline, and never state a performance number for resilience4cata that has not been measured.
- Preview the site locally: `./gradlew :site:serve` (http://localhost:3000, `-Pport=<n>`), which generates it and serves it with GitHub Pages' URL rules; a plain static server cannot serve history-mode URLs on reload.
