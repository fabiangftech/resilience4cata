# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

resilience4cata provides resilience annotations for plain Java 21+ with no Spring, CDI, AspectJ, agents, runtime proxies or reflection fallback. An annotation processor generates straight-line Java at compile time. 1.1.0 is released and `main` is 1.2.0-SNAPSHOT, so **the API, generated code and configuration must stay compatible within 1.x** (`docs/en/reference/compatibility.md`).

Read before design work: `docs/en/design.md` (decisions), `docs/en/architecture.md` (internals, concurrency), `docs/en/policies/README.md`. Module-by-module notes from the previous, much longer version of this file: `git show 50b007b:CLAUDE.md`. Check them against the code, since they may have aged.

## Commands

The build needs JDK 17+ to run Gradle, and toolchains for Java 21 and Java 25 (`micronaut` only). The configuration cache is on, so build logic must stay compatible with it.

```bash
./gradlew build                                              # compile, test, javadoc for every module
./gradlew :core:test --tests 'dev.resilience4cata.SomeTest'         # one test class
./gradlew :core:test --tests 'dev.resilience4cata.SomeTest.method'  # one test method
./gradlew build -PtestJdk=25                                 # run tests on another JDK (CI: 21 and 25)
./gradlew :examples:test                                     # end-to-end tests against real generated code
./gradlew :examples:test --tests '*DocsTest*' :site:test     # check documentation changes
./gradlew :site:serve                                        # preview docs on http://localhost:3000 (-Pport=<n>)

# Compatibility
./gradlew :core:apiCompatibility                             # japicmp against r4c.apiBaseline
./gradlew :examples:check -Pr4c.generatedBy=baseline         # code generated by the baseline release on this build

# Framework integrations
./gradlew :spring:test
./gradlew :micronaut:test
./gradlew :quarkus:it:check
./gradlew :native:spring:nativeTest                          # also :native:micronaut, :native:java; needs GraalVM for JDK 25 in GRAALVM_HOME, even for --dry-run

# Performance and concurrency
./gradlew :benchmark:allocationCheck                         # allocation gate (B/op budgets)
./gradlew :benchmark:jmh -Pjmh="RetryBenchmark -prof gc"     # results in benchmark/build/jmh/results.json
./gradlew :stress:jcstress -Pjcstress="-m quick -t CircuitBreaker"  # regex on the test class name
./gradlew :stress:test                                       # Lincheck model checking
./gradlew :mutation:pitest -Pmutation.targets='dev.resilience4cata.generated.RetryPolicy*'
infra/bench.sh <base> HEAD [regex]                           # base vs new on AWS: creates paid resources, reads keys from .env
```

There is no separate lint task: compilation uses `-Xlint:all -Werror`, and that applies to generated code too. Failing model tests replay with `-Ptest.seed=<n>`, and processor or config fuzz cases with `-PfuzzSeed=<n>`.

## Architecture

**Flow.** `processor` (`ResilienceProcessor`) reads the annotations and generates `<Type>$Resilient`. Interfaces get a wrapper, used through `Resilient.of(type, impl, registry)`. Annotated classes get a subclass (`SubclassWriter`), used through `Resilient.create(...)`, so self-calls are intercepted only in that style. Generated code calls the allocation-free permit protocol (acquire / onSuccess / onFailure) in core's `dev.resilience4cata.generated` package. If the generated class is missing, startup fails with a message naming the dependency to add.

**Modules.** `annotations` (`compileOnly` for users, `CLASS` retention) and `core` have no external dependencies except JSpecify as an `api` of core. `processor` is only ever on the processor path. `config` resolves properties, environment (`R4C_…`) and system properties (`r4c.…`). `all` and `bom` hold no code. `testkit`, `junit`, `micrometer`, `opentelemetry`, `reactor`, `spring`, `micronaut` and `quarkus:{runtime,deployment}` are published. `examples`, `benchmark`, `stress`, `mutation`, `site`, `native:*` and `quarkus:it` are not. Build logic lives in Java convention plugins under `conventions/`, and versions in `gradle/libs.versions.toml`.

**Policy order**, outermost first: `Fallback → Retry|Hedge → CircuitBreaker → RateLimiter → AdaptiveLimit → Timeout → Bulkhead → method`. Each policy is a `Kind` in `ResilienceProcessor`, declared in this order. `@PolicyOrder` can change it per method, so code generation must read `model.layers()`, never the `Kind` order. The fallback always stays outermost, and `Pipeline` keeps the default order.

**Attribute merging** (`PolicyAttributes`) counts only explicitly written, non-sentinel values. With `Resilient.of`, only interface annotations count. For annotated classes the precedence is interface < interface method < class < class method. Print types in generated signatures with `TypePrinter`, never `TypeMirror.toString()`.

**Configuration** is resolved once when an instance is created and is immutable afterwards. There is no hot reload or `reconfigure()`, by decision.

**Compatibility is enforced by tests:**

- Code generated by processor `1.a` must run on core/reactor `1.b` for every `b >= a`. Public members that generated code calls are binary API for the whole major, so change them only by adding.
- `contract/` lists metric names, snapshot paths, error codes and config keys, compared by a `ContractTest` per module. Removed or changed lines are a break. Added lines are copied from `<module>/build/contract/`. The `Contract` helper is duplicated in five modules, so keep the copies in sync.
- When an event or snapshot record gains a component, keep its previous canonical constructor.

**Errors.** Every error has a stable `R4C-<AREA>-nnn` code, through `ProcessorError` in the processor and `ErrorCode` at runtime, with a section in `docs/*/errors.md`. `ErrorCodeTest` checks them.

## Rules for code

- **Java 21 baseline** (`--release 21`) in published modules, with no preview or newer APIs. The only exception is `micronaut` (`--release 25`).
- **No Kotlin anywhere**, including the build. Gradle uses a minimal Groovy DSL.
- **No third-party Gradle plugins in the library's build.** Unpublished test projects use the official tools (Quarkus, Spring Boot, GraalVM Native Build Tools), never a home-made replacement. SonarQube at the root is the one other exception.
- **Dependencies:** adopt a release only once it is at least two weeks old.
- **Generated code stays straight-line and per method.** Do not route it through a shared lambda executor, which measured at double the overhead.
- **Hot paths:** no allocation on success paths, no locks or `synchronized` (pinning on JDK 21), no clock read unless the feature needs it, preallocated stackless rejections, and events allocated only when someone listens. Keep per-call methods small and move cold branches into their own methods, because inlining budgets are measurable here. Include JMH numbers before and after (one and four threads) when touching one.
- **Races are tested deterministically** through package-private seams, never with timing, and lock-free code also with jcstress. Mutation-check every new race test, and rerun jcstress after any change to a lock-free policy. Tests must survive GitHub's two-core runners.
- **Benchmarks against Resilience4j** use equivalent configuration, and any fairness adjustment is written in the benchmark's Javadoc.

## Rules for documentation

- `docs/en` is the source of truth. `docs/es`, `docs/pt` and `docs/zh` must keep the same file tree and receive every change. Code stays in English, and code blocks are copied unchanged. Portuguese and Chinese headings carry the English heading's id with `:id=`. New pages go in all four `_sidebar.md` files.
- Code blocks are tested. `<!-- snippet: id -->` must match a `// tag::id[]` region under `examples/src/test`. In `start/`, `policies/` and `guides/`, every `java` block is a snippet or has `<!-- not-compiled: reason -->`.
- A new policy attribute needs a row in `reference/configuration.md` in every language (`ConfigurationReferenceTest`).
- Never state a performance number that was not measured. Use a `> [!MEASURED]` callout citing its section of `docs/en/benchmarks.md`.
- Blog posts keep the versions they were written for, so leave them out when bumping versions after a release.
- Work toward and after 1.0 is tracked in `docs/en/plan-1.0.md`: mark a task `[x]` in the pull request that does it, with its number. Releases follow `docs/en/releasing.md`.
