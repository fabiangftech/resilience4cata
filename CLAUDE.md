# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

resilience4cata is an annotation-driven resilience library for plain Java 21+ (no Spring/CDI/AspectJ), designed to have lower overhead than Resilience4j. The project is in **phase 2: first code**. All six MVP policies are implemented end to end, sync and async: `@Fallback`, `@Retry`, `@CircuitBreaker`, `@RateLimiter`, `@Timeout` and `@Bulkhead`; plus the `config` module (external configuration), classifiers, the programmatic `Pipeline`, events and snapshots, and the `testkit` module.

## How the pieces fit

- Each supported policy is a `Kind` in `ResilienceProcessor` (annotation, generated field prefix, runtime policy class, registry method, config class). Kinds are declared in nesting order, outermost first: `FALLBACK`, `RETRY`, `CIRCUIT_BREAKER`, `RATE_LIMITER`, `TIMEOUT`, `BULKHEAD`. `writeMethod` emits one layer per policy present: the public method holds the outermost layer, and each inner layer is a private method `r4c$<field><index>(...)` with the same signature, ending with the delegate call. Each layer builder (`retry`, `circuitBreaker`, `timeout`) receives the inner call as an expression. Adding a policy means a new `Kind` in the right position, its attribute validation in `policyModel`, a layer builder, a `*Config` record + builder, a `*Policy` class in `dev.resilience4cata.generated`, and registry methods.
- `processor` (`ResilienceProcessor`) scans every root element (`getSupportedAnnotationTypes` is `*`, because composed annotations are user-defined). For each interface that uses `@Retry`, directly, at type level or through a `@ResiliencePolicy` bundle, it writes a top-level class named `<binary name>$Resilient` (for example `Repository$Cache$Resilient`) in the same package. The class implements the interface, delegates every method, and holds one `final` `RetryPolicy` field per protected method.
- Attribute merging is in `PolicyAttributes` (one instance per policy annotation): only explicitly set, non-sentinel values count. Precedence is declaring interface < wrapped interface < method; a direct annotation beats bundles; two bundles disagreeing is a compile error. Durations are parsed at compile time (`Durations`) and emitted as `Duration.ofNanos(...)`.
- Types in generated signatures are printed by `TypePrinter`, never `TypeMirror.toString()`, so type-use annotations such as `@Nullable` do not produce invalid source.
- At runtime, `Resilient.of(type, impl, registry)` loads `<type>$Resilient` once by name and calls its `(type, ResilienceRegistry)` constructor. The constructor calls `registry.retryPolicy(instanceId, name, config, overrides)`, which resolves defaults → named config → annotation overrides into an immutable `RetryConfig` and shares instances by `name`.
- The generated retry loop calls `RetryPolicy.start()`, `onFailure(attempts, e, start)` and `pause(delay)` (package `dev.resilience4cata.generated`, exported only for generated code). Nothing is allocated on the success path.
- `CircuitBreakerPolicy` (also the public `CircuitBreakerHandle` returned by `registry.circuitBreaker(id)`, with `forceOpen`/`disable`/`reset`): the state is an immutable `Phase` (`Closed`/`Open`/`HalfOpen`/`ForcedOpen`/`Disabled`) swapped by CAS through a `VarHandle`; objects are allocated only on transitions. Every transition goes through `transition(...)`, which swaps the phase and then clears `quiet`. `Closed` holds a `SlidingWindow`: `CountWindow` (default) or `TimeWindow` (one-second buckets, `LongAdder` counters, never quiet because every success must be counted). `acquire()` returns the phase's generation as the token, and outcomes with a stale token are dropped. `CountWindow` is a slot array updated with `getAndSet` plus counters, and skips rewriting a slot that already holds the same outcome. While closed with a window of only fast successes, the policy's `quiet` field holds the generation and `acquire`/`onSuccess` read only that field (ordering: count a failure before clearing `quiet`; set `quiet` before re-checking the window). Reads of `phase`/`quiet` are opaque, which is safe because everything they reach is `final`.
- Performance rules learned while tuning the breaker (see `docs/en/benchmarks.md`): under contention, writes to shared cache lines cost far more than locks or atomics save, so never write a value that does not change and keep per-call-written fields (the window cursor) apart from read-mostly ones. On ARM, avoid acquire/volatile reads on the hot path where `final`-field publication already suffices, and use the weakest atomic that is correct (`compareAndExchangeAcquire` to take a permit, `getAndAddRelease` to give it back): full-fence atomics cost 2–3× more there. Measure single-thread and multi-thread, success and mixed, after every hot-path change: improvements to one case have regressed another more than once. Rejections throw one preallocated, stackless `CallNotPermittedException` per breaker. Calls are timed only if `slowCallDuration` is set. `RetryConfig.DEFAULTS` aborts on `CallNotPermittedException`, so an open breaker stops retries.
- `TimeoutPolicy` + `Watchdog`: one shared daemon thread publishes a coarse clock and checks, every tick, a per-thread stack of reusable `Scope`s; timed calls read no clock and write only their own scope. A scope's state is a stamp (call number in the high bits, state in the low two) so a watchdog that read an earlier call cannot interrupt the next one (ABA). On the caller side, `RUNNING → IDLE` by CAS; if the watchdog won, wait for `TIMED_OUT`, clear the interrupt, throw `CallTimeoutException`. Tests use a manual `Watchdog(0)` advanced with `tick(nanos)`. RUNNING→IDLE is `compareAndExchangeAcquire` (release alone would let the next call's start/limit be seen with this call's stamp → early interrupt). The Watchdog's coarse clock advances by at most one tick per tick (`advance`), so a late wake-up of the watchdog thread can't make calls look older than they are; it parks ¾ of a tick. Async timeouts use `TimeoutTimer` (not `AsyncSupport.later`, which stays on an STPE for precise retry and rate-limiter delays): `schedule` is one release CAS onto a per-thread-id striped inbox; each tick the timer thread unlinks cancelled entries, drains the inboxes (deadline = clock at drain + duration, so never early), and fires expired lane heads on virtual threads; at most ~2 ticks late. `TimerEntry` states go NEW→SCHEDULED→FIRED, or →CANCELLED by CAS. `executeAsync` skips the timer for a `CompletableFuture` that is already complete. Tests use `new TimeoutTimer(launched::add)` with `tick(now)` or the separate steps `drainCancelled/drainNew/expire`.
- `BulkheadPolicy` (also `BulkheadHandle`, from `registry.bulkhead(id)`): with `maxWait = 0`, a CAS loop on a counter in a padded object; a full bulkhead only reads. With `maxWait > 0`, a non-fair `Semaphore`. `waitingCalls()` = queued async waiters + `Semaphore.getQueueLength()` (0 without `maxWait`); monitoring only, never on the hot path. An interrupted wait is a rejection with the interrupt flag set again, so an outer `@Timeout` turns it into `CallTimeoutException`. Async calls with `maxWait > 0` never block: a full bulkhead queues a `BulkheadWaiters.Waiter` (FIFO `ConcurrentLinkedQueue` plus a padded volatile `count` of unclaimed waiters), whose one-shot state is CASed `WAITING → CLAIMED` by either the hand-off or its timeout (`AsyncSupport.later`), never both. `exit()` releases the permit, then does one volatile read of `count`; if it is positive it takes a permit back and gives it to the oldest live waiter on a new virtual thread. Enqueue order is count++ → offer → timer → drain, so release/read and count/tryAcquire form a store-buffering pair with volatile accesses on both sides: no lost wake-up. A drain that loses the permit hands nothing off; a permit no live waiter can take goes back to the semaphore. When sync threads are blocked too, every other hand-off leaves the slot to them (approximate: woken sync threads can win anyway). Tests replay the races through `enqueueForTest`/`drainForTest`/`Waiter.claim()`.
- `FALLBACK` is special: it has no registry entry, `name` or `config`, and is validated by `fallbackModel` (handler class or sibling methods) into a `FallbackModel` on `MethodModel`, not into `policies`. Its statements come from `fallbackLines`, which always end the method and expect the failure in a catch parameter named `r4c$e` (so `throw r4c$e` is a precise rethrow). Without `@Retry` it is its own outermost layer; with `@Retry` it is fused into the retry layer's give-up branch, which is how `FallbackContext.attempts()` gets the count without per-call allocation. Sibling methods are sorted most specific exception first; emission stops after the first one that catches everything, since later code would be unreachable. The runtime side, `FallbackPolicy`, only runs after a failure: `handles` (cached per class, `skipOn` wins), `context(...)`, and `unchecked(...)` for handler exceptions the method does not declare.
- `config` (`ResilienceConfig`): reads classpath resources, files, `Properties`, environment (`R4C_…`) and system properties (`r4c.…`) into typed settings (keys parsed by `Key`, env names by backtracking in `Sources.EnvironmentNames`, attributes declared once per policy in `PolicyType`), applies profiles and flattens `extends`, validates eagerly against the built-in defaults, and registers `*Defaults`/named configs on a `ResilienceRegistry.Builder` via `applyTo`. Adding a policy attribute means one `Attribute` line in `PolicyType`. Every problem is collected into one `ConfigException` with an `R4C-CFG-nnn` code, the key's source (file and line) and a suggestion. `PropertiesReader` mirrors `java.util.Properties` syntax but keeps line numbers. Its `Durations` duplicates the processor's grammar: keep them in sync.
- `RateLimiterPolicy` (also `RateLimiterHandle`, from `registry.rateLimiter(id)`): GCRA on one padded `long`, the theoretical arrival time `tat`. Each permit moves `tat` by `interval = period / permits`; a call passes if `tat` stays within `permits × interval` of now. One loop serves both modes: if the needed wait exceeds `maxWait` (0 when fail-fast) it rejects without writing, otherwise a CAS reserves the slot and the caller sleeps until it is due (an interrupted sleep gives the permit back). A caller that loses the CAS parks for 1 ns before retrying: under contention that cut 658 → 131 ns per call with four threads, where other atomics, spinning and `Thread.yield()` did not help. `tat` guards no other memory, so it uses plain CAS (`weakCompareAndSetPlain`) and opaque reads. nanoTime values are compared by subtraction, never `Math.max`, because they can wrap. Tests use the package-private constructor with a fake ticker and sleeper.
- Races that a stress test cannot reproduce reliably are tested deterministically through package-private test seams that replay the interleaving (`phaseForTest`/`publishQuietForTest`). When adding such a test, check it by mutation: remove the guard it protects and confirm the test fails. Delete the test-result XML first and make sure the mutant compiles: if it does not, Gradle leaves the old XML behind and the check looks like a pass.
- Every `ClassValue` on the same class shares that class's small lookup cache: an extra `ClassValue` per policy (even one never queried) made failure-path lookups collide and contend under four threads (37 → 57 ns, bimodal forks). Keep one `ClassValue` per policy and return a richer value (`RetryPolicy.Verdict`) instead of adding another.
- Keep per-call methods small: cold branches (timed out, event publishing) go in their own methods. Adding one call to the timed-out branch of `TimeoutPolicy.end` cost 1.4 ns per call on one thread through JIT inlining, though the branch never ran.
- `System.nanoTime()` costs about 21 ns single-threaded and 160+ ns under contention on macOS (HotSpot keeps it monotonic with a global CAS). Avoid clock reads on hot paths unless the feature needs them (slow-call detection, time windows).
- Async: a method returning `CompletionStage<T>` or `CompletableFuture<T>` (concrete `T`; `asyncResult` in the processor) is generated by `writeAsyncMethod` as one expression of nested `policy.executeAsync(() -> next)` calls, innermost the delegate, with `AsyncCall<T>` (may throw) as the lambda type. A fallback becomes a private `r4c$recover<index>(Throwable, int attempts, params...)` returning a stage, passed as a `Recovery<T>` to `RetryPolicy.executeAsync(call, fallback, recovery)` (so it gets the attempts) or to `FallbackPolicy.executeAsync`. This deliberately breaks the straight-line rule: async calls allocate futures and go through megamorphic `CompletableFuture` callbacks anyway, so a lambda per layer costs little there; the sync path is unchanged. `AsyncSupport` holds the single daemon timer (`ScheduledThreadPoolExecutor`, remove-on-cancel) and hands every fired task to a new virtual thread, so user callbacks never run on the timer. Failures are always unwrapped from `CompletionException`/`ExecutionException`.
- `classifier` (`@Retry`/`@CircuitBreaker`): validated by `ResilienceProcessor.classifier(...)` (concrete, non-generic, accessible no-arg constructor, implements `Classifier<X>` with the value type assignable to `X`); `PolicyModel.classifier` holds the class name. Each method gets a `final` field `<field>Classifier<index>`; the breaker reuses the retry's when the class is the same. Methods without a classifier generate byte-identical code. Layers `classifiedRetry`/`classifiedCircuitBreaker` call `classify` directly (monomorphic), then `RetryPolicy.onFailure(..., Outcome)`/`onFailedResult` or `CircuitBreakerPolicy.onFailure(..., Outcome)`/`onResult` (`IGNORE` → `release`, which returns a half-open permit). Every retry decision goes through the private `RetryPolicy.decide`. The classifier replaces `retryOn`/`recordOn` (combining them is a compile error); `abortOn`/`ignoreOn` win first. An exhausted `FAILURE` result returns the last result and never triggers `@Fallback`. A throwing classifier fails the call: the breaker records `FAILURE`, the retry gives up through the fused fallback (`fallbackLines` takes the failure variable name, here `r4c$c`, with `attempts + 1`), without a `GaveUp` event (known gap). Async uses the `executeAsync(call, classifier, ...)` overloads.
- `Pipeline` (programmatic API, package `dev.resilience4cata`): one final class with nullable `final` policy fields, built by `Pipeline.builder(registry, id[, type])` with optional `.retry/.circuitBreaker/.rateLimiter/.timeout/.bulkhead(config?, overrides?)`, `.classifier/.retryClassifier/.circuitBreakerClassifier`, `.fallback(Function)`/`.fallbackHandler(FallbackHandler)` + `fallbackApplyOn/SkipOn`. `build()` gets policies from the registry's public `xPolicy(id, "", config, overrides)` and `fallbackPolicy(...)`, so the id is the instance key (shared like an annotation `name`) and listeners apply. `execute(PipelineCall<? extends T, X>) throws X` runs the generated protocol in small private per-layer methods (unused layer = one null check; fallback fused into the retry give-up branch for `attempts`; precise rethrow keeps `X`) and allocates nothing on success (`PipelineTest.theSyncSuccessPathDoesNotAllocate`). `executeAsync` nests each policy's `executeAsync`, one lambda per layer. Its single `call.call()` site goes megamorphic across pipelines (`PipelineBenchmark.pipelinePolluted`); annotations stay the fast path. `PipelineEquivalenceTest` (examples) checks it behaves like generated code for the same config.
- `PolicyEnvironment` (generated) is built once per registry by `PolicyEnvironment.of(ticker, random)` from `Builder.ticker(Ticker)`/`random(RandomGenerator)`, plus `withEvents(EventDispatcher)`, and passed to every policy's `(id, config, env)` constructor; policies copy what they need into `final` fields. `DEFAULT` shares one `System::nanoTime` lambda (call sites stay monomorphic) and `ThreadLocalRandom` (`random == null`, checked only on the retry failure path). With a `Ticker` (testkit's `ManualClock`): reads and sleeps go to the ticker, async delays (`env.later`, used instead of `AsyncSupport.later` by every policy) and async timeouts go to `ticker.schedule`, and sync timeouts use a per-registry `Watchdog.manual` (tick 0, no slack) ticked through `ticker.onAdvance`. Not covered: sync bulkhead `maxWait` (Semaphore, real time). New policy code that schedules must go through `environment.later`, never `AsyncSupport.later` directly.
- Events (`dev.resilience4cata.event`): sealed `ResilienceEvent` → per-policy sealed interfaces with record events. Listeners are registered only on `ResilienceRegistry.Builder.listen(...)` and stored as an immutable `EventDispatcher` in `PolicyEnvironment.events`. Each policy constructor resolves one `@Nullable EventSink<Record>` per event type it publishes (`env.events.sink(type, id)`, filtered by type and instance) into a `final` field. Emit sites are `if (sink != null) sink.publish(new Event(...))`, reading the clock only inside, so unused events cost one null check on non-success paths and nothing on success paths. Breaker transitions are published inside `transition()` after the CAS (exactly once; `EventStress` checks it). Rejections are published at the `REJECTED`/`false` returns. Retry events in `RetryPolicy.decide`. Fallback events in `FallbackPolicy.handles` (generated code gets the policy from `registry.fallbackPolicy(...)`). `EventSink.publish` passes listener exceptions to the thread's uncaught exception handler. Never allocate an event before the null check: `EventPublishingTest.rejectionsAllocateNothingWithoutListeners` measures it.
- `registry.snapshot()` and `*Handle.snapshot()` build clamped read-only records off the call path (`SlidingWindow.counts(now)`); timeouts are kept in the registry only for snapshots. There are no per-call counters: adding totals would be a per-call shared write and needs a benchmark first.
- `testkit` (`resilience4cata-testkit`, depends on `core` only, no JUnit): `ManualClock implements Ticker` (sleep = advance; due tasks run inline on the advancing thread in deadline order, outside its lock), `ResilienceTesting.registry(clock[, seed])`, `elapseWaitInOpen`.
- Not supported yet, and rejected by the processor with an explicit error: wildcard or custom async return types, annotations on classes, `@Fallback` on generic methods.
- The processor is registered with Gradle as **isolating** (`processor/src/main/resources/META-INF/gradle/incremental.annotation.processors`). Each `<Interface>$Resilient` is written with the interface as its only originating element, and every decision (generation and errors) must use only what is reachable from that interface: its annotations, bundle annotation types, handler classes referenced from them, superinterfaces. Never read other root elements or keep cross-interface state. Aggregating is not an option: with `getSupportedAnnotationTypes() = "*"` Gradle would reprocess every source and rebuild fully whenever a SOURCE-retention annotation such as `@Override` is present. `IncrementalProcessingTest` checks the registration, the originating elements, and that recompiling one interface against class files generates the same source.

Start with `docs/en/README.md` (decisions and open questions), then `docs/en/features.md` and `docs/en/architecture.md`. The detailed research behind them is in `docs/en/research/01–05`.

## Decisions to respect

- **Java 21 baseline** (`--release 21`), tested on 21 and 25. Do not use APIs that are preview or newer than 21 (e.g. `StructuredTaskScope`, the Class-File API) in published modules.
- **No Kotlin anywhere**, including the build. Gradle uses the Groovy DSL, kept minimal and declarative (`settings.gradle`, short `build.gradle` per module). All build logic goes in convention plugins written in Java under `conventions/src/main/java` (plugin `r4c.java-library`: Java 21 toolchain, `--release 21`, `-Xlint:all -Werror`, JUnit Platform, `resilience4cata-<module>` jar names). Versions live in `gradle/libs.versions.toml`.
- Interfaces referenced by annotations (`FallbackHandler<T>`, `Classifier<T>`) live in `core`; annotation attributes are `Class<?>` and the processor checks the type. This keeps `annotations` `compileOnly`.
- **Coordinates**: groupId `dev.resilience4cata` (the project owns `resilience4cata.dev`); root Java package and JPMS module prefix `dev.resilience4cata`.
- **`annotations` is a separate module from `core`.** Durations in annotations and config are strings (`"250ms"`, `"2s"`, `"PT2S"`), validated by the processor.
- **Modules have single-word names**: `annotations`, `core`, `processor`, `config`, `micrometer`, `testkit`, `bom`, plus unpublished `benchmark`, `stress`, `examples`. Never name a module `test` (clashes with Gradle's `test` task). Published artifactIds get the `resilience4cata-` prefix.
- **Annotations are handled by a compile-time annotation processor (`processor`) that generates plain Java source.** No runtime proxies, bytecode generation, AspectJ or agents in `core`. The processor is **mandatory**: if a generated class is missing, `Resilient.of` must fail fast with a message showing the `annotationProcessor` dependency to add; there is no reflection fallback. Annotations use `CLASS` retention, so `annotations` is a `compileOnly` dependency for users.
- **`core` and `annotations` have zero external dependencies** (JDK only, except JSpecify as an `api` dependency of `core`). `processor` is only ever an `annotationProcessor` dependency. Generated code may only use `core`'s exported generated-code API.
- **Generated code must be straight-line and per method**, calling the allocation-free permit protocol in `core` (acquire / onSuccess / onFailure). Do not route generated code through a shared lambda executor: our JMH run showed it doubles the overhead once several services share it (see `docs/en/research/02-annotation-mechanisms.md` §3).
- **Hot paths**: no allocation on success paths, no locks and no `synchronized` (pinning on JDK 21), one clock-read pair per call, preallocated stackless rejection exceptions, events allocated only when someone listens. Configuration is resolved once at instance creation, never per call, and is immutable afterwards: there is no hot reload or `reconfigure()` API, by decision.
- **Interface vs implementation annotations**: with `Resilient.of(interface, impl, registry)` only interface annotations count (annotating the implementation is a compile error). In the future subclass style, implementation annotations win attribute by attribute: interface < interface method < class < class method.
- **Self-invocation is intercepted** in the generated-subclass style (`this.other()` goes through the override). It cannot be intercepted in the interface-wrapper style; that limit is documented, not worked around.
- Default policy order, outermost first: `Fallback → Retry|Hedge → CircuitBreaker → RateLimiter → AdaptiveLimit → Timeout → Bulkhead → method`.

## Commands

```bash
./gradlew build                                   # compile, test, javadoc for every module
./gradlew :core:test                              # tests of one module
./gradlew :core:test --tests 'dev.resilience4cata.SomeTest'          # one test class
./gradlew :core:test --tests 'dev.resilience4cata.SomeTest.method'   # one test method
./gradlew :examples:test                          # end-to-end tests against real generated code
./gradlew :testkit:test                           # ManualClock and the policies on a manual clock
./gradlew :benchmark:jmh -Pjmh="RetryBenchmark -prof gc"   # JMH; options after -Pjmh, results in benchmark/build/jmh/results.json
./gradlew :benchmark:jmh -PjmhJdk=25              # benchmarks on another JDK
./gradlew :stress:jcstress -Pjcstress="-m quick"                      # jcstress concurrency tests; report in stress/build/jcstress/results/index.html
./gradlew :stress:jcstress -Pjcstress="-m quick -t CircuitBreaker"    # one group (regex on the test class name)
infra/bench.sh 3bc496f HEAD [regex]              # every benchmark on ~19 EC2 machines in parallel, base vs new; ~20 min; reads AWS keys from .env
```

For base-vs-new comparisons use `infra/bench.sh` (Terraform in `infra/`, planner and summary in `infra/plan.py`): it compiles both revisions locally, ships the benchmark runtime classpaths to S3, and runs each benchmark method at each thread count for both revisions back to back on the same `c7g.xlarge` (Graviton3, no SMT, fixed clock; machines differ by 0.1% on the calibration benchmark), then destroys every resource. The account allows only 3 spot instances, so `SPOT_MACHINES=3` and the rest are on-demand; spot instances must not set `instance_initiated_shutdown_behavior`. Results land in `benchmark/build/aws/<run>/summary.md`. Graviton numbers are not comparable with the Apple Silicon sections of `benchmarks.md`. A per-fork bimodal result (`rawData` in the JSON) points at a layout or cache effect, not noise: check it before calling a difference noise.
Benchmarks (`benchmark` module, plugin `r4c.jmh` in `conventions`) use plain JMH (annotation processor + `org.openjdk.jmh.Main`), no third-party Gradle plugin. Every comparison with Resilience4j must use equivalent configuration and document any adjustment made for fairness in the benchmark's Javadoc (for example `resilience4jRetryOnceNoSleep`, which removes Resilience4j's unconditional `Thread.sleep(0)`).

Where tests go:
- `core`: unit tests of policies and config. `RetryPolicy` has a package-private constructor that takes a fake clock and sleeper.
- `processor`: compile Java sources in-memory with the processor via the `Compilation` helper (plain `javax.tools`, no compile-testing library) and assert on errors or generated source. Compilation uses `-Xlint:all -Werror`, so generated code must be warning-free.
- `examples`: annotated interfaces under `src/test/java` are processed by `testAnnotationProcessor project(':processor')`; tests call `Resilient.of(...)` on them. Generated sources land in `examples/build/generated/sources/annotationProcessor/java/test`.
- `testkit`: tests of `ManualClock` and of the policies driven through a registry on a manual clock. Users' own deterministic tests should use it too (see `TestkitEndToEndTest` in `examples`).
- `stress`: jcstress tests (`@JCStressTest`) of the lock-free policies. `./gradlew build` only compiles them; they run through the `jcstress` task (plugin `r4c.jcstress` in `conventions`: annotation processor plus `org.openjdk.jcstress.Main`, no third-party Gradle plugin). Tests that need package-private seams (fixed clocks, `Watchdog(0)`/`tick`, stale stamps) live in package `dev.resilience4cata.generated`, which works because `stress` is not modular, so `core` is on the class path. Check every new test by mutation, as for other race tests. Rerun them after any change to a lock-free policy.

The build runs on any JDK ≥ 17 and compiles with a Java 21 toolchain (auto-detected locally). Configuration cache is on: build logic must stay configuration-cache compatible.

## Documentation rules

- Docs are plain Markdown, **bilingual**: `docs/en/**` and `docs/es/**` must have the same file tree. English is the source of truth; any change to an English doc must be mirrored in the Spanish one. Code and identifiers stay in English in both.
- `docs/` is a Docsify site, not a Gradle module. Sidebars are `docs/en/_sidebar.md` and `docs/es/_sidebar.md`; add new pages there. Keep Markdown tool-neutral (CommonMark/GFM plus Mermaid fences).
- Research docs tag claims as verified, measured or inferred. Keep that discipline, and never state a performance number for resilience4cata that has not been measured.
- Preview the site locally: `python3 -m http.server -d docs 3000` (or `npx docsify-cli serve docs`).
